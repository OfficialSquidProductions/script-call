# Local Locations and On Call preview

The initial feature commit e38c444 was validated locally on Script Call 0.3.9. Its development preview is with updater downloads/installation disabled and dedicated project, preferences, log, diagnostic and backup storage. It does not replace the installed app. At that initial local checkpoint, no user production was edited and no source, feed, release or website had been published.

Production Data → Locations presents two independent groups: Shooting location and Parking / base camp. Each has a Google Maps link first, a manually editable address/directions field, an explicit reviewed-link-text action and an Open in Google Maps button. Legacy `address` and `parking` strings remain in place so existing drafts, imports and template-specific basecamp overrides keep their semantics. Existing shooting coordinates are unchanged; optional parking coordinates are independent. Both coordinate pairs are at the bottom in a native collapsed Advanced disclosure. Parking coordinates do not affect shooting weather/solar.

Only explicit search/destination text embedded in supported HTTPS Google Maps URLs is suggested. Suggestions may be venue names, so they are labeled for review, not presented as geocoded/verified street addresses. A link edit never replaces manual address text; the clearly labeled Use/Replace action is required. Query text is decoded locally even offline. Short links, opaque place IDs, `/place/` slugs and camera coordinates do not establish a street address; open the map and copy/enter the address manually. No background network request, reverse geocoder, paid API or credential is used. Opening a map sends only that link or manual address search to Google through the default browser; it may require connectivity. Invalid links remain editable/savable but cannot be opened. Google hosts are allowlisted; unexpected sites, credentials, schemes and ports are rejected. Google country domains outside the supported allowlist can be handled by manual address search after clearing the link.

Google's documented Maps URL form: https://developers.google.com/maps/documentation/urls/get-started . Generated manual-address searches use its `api=1` and `query` parameters. No API key is required for this link workflow.

Crew availability adds **O/C — On Call (available, not on set)** as its own `on-call` state. It covers the entire marked production-local date with no time windows. Other dates remain unknown until entered; overnight duty still checks every date. Grid, editor and call-row advice identify On Call explicitly. It does not create/remove calls, change attendance, call/release times, person identity or PDF call-sheet attendance/status fields. Ordinary All Day remains distinct; cast choices remain unchanged. Existing issued PDF bytes stay frozen. Undo/redo, rename, restart, reimport and portable archives retain O/C.

O/C archives declare minimum reader version 5, so older Script Call readers reject the unsupported state clearly rather than misreading it. Older projects/archives remain readable here; ordinary availability retains reader version 4. No records are rewritten on load to add either feature.

- `node --test tests/*.test.cjs`: 113 passed, 2 optional private-provenance checks skipped. Existing updater loopback tests require the normal unsandboxed test environment; their first sandboxed attempt failed and was retained in the verification log. New tests cover URL parsing/safety, ambiguous and opaque URLs, manual override immutability, legacy coordinate preservation, independent parking, Production Desk merge, stable IDs, store reopen, archive round trips, exact issued PDF bytes, O/C/All Day/unknown/unavailable distinctions, overnight intervals and reimport.
- Built with `python3 tools/package_mac.py --preview --out 'build/location-maps-on-call-preview/Script Call.app'`; local ad-hoc signature verified. No notarization upload.
- Native Mac QA used CUA mouse/keyboard only, with synthetic records. Direct launch isolation, legacy/manual address preservation, explicit suggestion application, independent parking, short/invalid links, native Advanced disclosure, original coordinates and separate zero parking coordinates, actual external map search, new blank production/location, O/C selection/cancel/undo/redo, unchanged cast choices, call-row not-on-set advice, unchanged call assignment/time and direct reopen passed.
- Native UI issued and exported a real two-page G-Casper PDF, then edited the master address and exported it again: bytes matched exactly. Native portable export was read and imported in another isolated store, preserving location/person IDs, links, addresses, availability and the original PDF. General basecamp overrides and PDF renderers were not changed.
- Evidence lives in `verification/location-maps-on-call-*.json` / `*.txt` and `verification/location-maps-issued-{before,after}.pdf` (ignored local QA artifacts).

The initial local feature used native CUA QA and full unit coverage; prior release-specific automation approval was not reused. The later explicitly authorized 0.3.10 release passed the full packaged regression/smoke and real native-upgrade suites; see RELEASING.md. Windows, Linux, Intel Mac, physical touch and a formal screen-reader audit are untested. This preview is not a public signed/notarized distribution.
