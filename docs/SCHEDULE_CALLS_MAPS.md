# Schedule notes, personal calls, time display and Maps coordinates

Local candidate on top of Script Call 0.3.12. No version bump, release, installation or website/feed change is part of this work.

## Behavior

- Daily scene schedule rows edit notes instead of start, offset and duration. Notes initially follow the scene's reusable production notes; a daily override can be blank or multiline. “Use production scene notes” removes that override. Scene page lengths, order and historical timing fields remain stored. Break/move/meal timing still works. Newly generated daily and advance output uses the notes-first scene layout.
- Frozen issued snapshots without the new presentation marker retain their historical timed layout. Issued PDF bytes are never regenerated or rewritten. Long notes can continue across pages with repeating table headers.
- Cast availability no longer assumes production wrap is a personal release when assigned scenes are untimed. A valid personal call with an unknown end is neutral advice, distinct from a red conflict. Explicit preparation/release times and retained timed assigned scenes still contribute to the full interval. Crew still use explicit release or estimated wrap. Unknown availability is not confirmed availability or a hard conflict. O/C remains available, not on set.
- Personal Call stays visible. Other call/preparation/release times and day offset are under a collapsed keyboard-accessible Advanced disclosure. Values remain stored and checked.
- New cast calls default to that day's Shooting Call. New crew calls default to General crew call. Existing manual calls remain unchanged; a missing base stays blank. New calls record their default basis; legacy blank calls retain their prior crew-call inheritance. Chosen/default calls are never moved to an available window automatically. Red advisory warnings show the conflicting interval and allowed hours until corrected; saving and acknowledged issue remain possible.
- Settings & help offers 24-hour (military) and 12-hour (AM/PM) display. The production preference travels in portable projects and becomes the default for new productions on that device. Existing per-day clock choices remain the fallback until a production preference is selected. Inputs, availability windows/advice and newly generated output use the selected format. Stored HH:MM values and zones are unchanged. AM/PM is required in 12-hour inputs; invalid/incomplete edits preserve the last valid value and Escape cancels them.
- Shooting-location Maps links resolve explicit selected-place/pin coordinates after editing or through Resolve coordinates. Camera viewport coordinates are not a venue. Short-link redirects/canonical links are bounded and restricted to HTTPS Google Maps hosts, with response size/time limits. Unsupported or opaque links retain manual fallback. Existing/edited manual coordinates are protected; replacement needs the explicit Use Maps coordinates action. Lookup results are discarded after link/coordinate/project changes. Parking remains independent. Manual address text is never overwritten automatically.
- Existing NWS weather uses the selected shooting location, shoot date and effective zone. Requests retain explicit single-request consent. Periods must overlap the local calendar date; dates outside the approximately seven-day horizon, unsupported locations, offline/provider failures and stale forecasts are explicit. Stale forecast text is excluded from newly generated output. No paid service, API key or new credential is used.

## Compatibility and verification

Old projects load without migration writes. Additive notes, call-basis, coordinate-source and display fields require portable reader 8 so older apps fail clearly rather than silently lose them. Production Desk three-way reimport preserves those manual fields, stable IDs and availability. Existing recovery, updater, reporter, templates and import/export regression tests remain in the suite.

The Node suite passed 147 tests, with two pre-existing skips. Coverage includes all 1,440 minute values in both formats; call defaults/missing bases; valid boundaries, multiple/overnight windows, date/zone/DST handling, unknown/unavailable/full-day/O-C; note inheritance/blank overrides, four templates, retained historical timing, frozen legacy rendering; reader 8 save/reopen/portable copies and exact issued bytes; Maps host/redirect/body limits and manual/race protection; local-date NWS horizon/period/cache/offline cases; and Production Desk reimport.

Packaged Apple Silicon Mac QA used a dedicated embedded preview profile, including direct launch, settings, logs, diagnostics, backups and SQLite. Native UI checks exercised cast/crew defaults, valid/invalid/corrected warnings, explicit overnight release, Advanced controls, AM/PM validation and Escape, Settings persistence, notes editing/reset/multiline output, map-coordinate resolution/manual override/explicit replacement, live NWS retrieval at a public synthetic coordinate, availability AM/PM save/undo/O-C, blank production/missing shooting call, native save/reopen/export/import, acknowledged issue, new draft and frozen original preservation. An 85-line note generated four PDF pages; every numbered line was extracted and all pages visually inspected using macOS PDFKit. Final packaged source hashes matched the checkout. Synthetic issued PDF and snapshot hashes stayed unchanged after new draft and display edits.

All nine real saved production JSON hashes and all 650 installed app file hashes matched their read-only pre-test baselines. No real records were changed. No renderer diagnostic events were recorded in the preview profile.

The historical Playwright availability and G-Casper harnesses were adapted to seed retained scene timing through disposable fixtures, since that editor is intentionally removed, and to open Advanced before editing hidden fields. They were syntax-checked, not executed: the previous release-specific automation grant does not cover this local candidate. Native CUA and unit/data checks above were executed. Windows/Linux UI, release signing/notarization, updater acceptance and public distribution were not run for this local feature. Live short-link resolution was not tested against a real short-link fixture; redirect behavior is covered by deterministic mocks. Opaque IDs, viewport-only links, unsupported redirects and regional/network failures may still require manual coordinates/address. Resolved coordinates are suggestions to confirm, not verified venue geocoding.
