Your first call sheet

  1. Start a production. Create a new production or choose Load The Last Light Demo to explore a separate fictional example.
  2. Set up the day. Review the shooting date, timezone, unit, general call, locations, parking, and emergency information.
  3. Build the calls. Add the daily schedule, cast calls, crew calls, notes, and advance schedule.
  4. Choose a layout. Open Templates & layout, select G-Casper-style or Original Narrative, then choose paper and output preferences.
  5. Preview and review. Check the printed front and back. Resolve required details before using Review & issue.
  6. Export and back up. Use Export PDF for a readable handoff and Export project for an editable .callsheet archive.

Production Desk import

Export your production from Production Desk, then choose Import Production Desk in Script Call. Review the mapping preview before committing changes. Imported calls, performers, crew, timezone, and emergency details still need review.

On a later import, review the comparison against the prior imported baseline. Manual edits, explicit blanks, saved layouts, and issued days are preserved. Keep your original Production Desk export for its embedded PDF attachments.

Common questions

Does switching templates erase my information?

The same day data stays in the project when templates change. Hidden sections remain editable. G-Casper-style keeps crew on a separate back, and dense content can continue onto extra pages.

Can I revise an issued sheet?

Issued revisions retain their original PDF bytes. Make a new revision for changed information, review it, then issue deliberately. An import never automatically issues a sheet.

Where should I keep a backup?

Use Create local backup and export a portable project. Keep an independent copy somewhere you control. A PDF is a handoff document; keep an editable project too.

How do updates work?

With automatic checks enabled, the app checks after startup and daily. You can also choose Check for updates. Select Download update, then Save, back up & restart. The app verifies the release, saves pending edits, and creates a local backup before installation. Older update-disabled prototypes need one manual installation of the current release. Failed or offline checks leave your current app usable.

Report a bug on GitHub. Avoid including private production records, contact lists, or unredacted call sheets in a public issue.
